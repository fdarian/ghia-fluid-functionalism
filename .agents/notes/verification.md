How the check scripts and screenshots verify behaviour without a browser, and the traps that make a check pass for the wrong reason; read before writing or changing a `apps/demo/scripts/check-*.tsx` or a screenshot scenario.

There is no browser to compare against. Verification is two headless harnesses on gpuix's offscreen test renderer: `pnpm screenshots` (captures per page) and `pnpm check:scenarios` (every `apps/demo/scripts/check-*` file, asserting behaviour, ARIA, focus and geometry). `check:scenarios` runs everything and lists all failures at the end. The test-renderer quirks of the screenshot harness are in the README under "Screenshots run on the test renderer".

## Checks

- Every check window opens at scale 1 (the test renderer's default), so results do not depend on which displays are attached. A check of another scale sets it after the first frame. A bare-view check (`createCheck` with a function target) carries the Inter `fontFamily` on its root as `App` does; without it the view is measured in the default font and cap and x heights come from the wrong face.
- Check against the browser or the source's behaviour, not a screenshot: each native loop has a check that holds the motion clock and reads the result (`check-file-thumbnail`, `check-thinking-indicator`, `check-carousel-dots`, `check-plain-vs-fluid`, `check-script-cursor`).
- A click after a spring needs still bounds, not a fixed wait. A spring's tail moves a box by fractions of a pixel long after it looks settled, and a count of polls is a count of frames, which a loaded machine runs fewer of. `kit.still(testIds, what)` in `check-kit` waits until every id is painted and its bounds have not changed for 150 ms of wall-clock time. Use it for any click on something a spring just moved.
- Do not add tolerance to make a geometry check pass. A failure in `check-weight-widths` or `check-tabs-subtle` (baseline within 0.01 px, cap top within 0.02 px of Chrome's) is a real move.
- A wheel check needs fractional content. 29 rows of 19.5 px plus 16 px padding (581.5 px) exposes a rounding mistake in the scroll range that whole-pixel content (28 rows) hides; `check-scroll-area` runs both contents and reaches the end by wheel, thumb drag and the End key. It also pins that a continuous wheel gesture stays latched to the area it started on (the latch holds until 500 ms pass without an event, as in Chrome).
- A scroll helper must not read "the element did not move" as "the page ended": a wheel can land without moving the page, so a capture could be taken with the element off-screen. `scrollNearTop` in `apps/demo/src/lib/demo-kit.tsx` counts consecutive wheels that moved nothing and throws on the third. Use it for any demo scenario that scrolls an element into view.
- Read the first frame of a page switch immediately: `check-site-nav` clicks a sidebar row and reads the scroll metrics at once, which draws what is pending, so it sees the new page's first frame. Reading after a settle passes even if the page was corrected a frame late.
- Presence exits only unmount if frames run: `settle()` flushes the tree and drains native events each frame, because a bare `flush()` never delivers `onMotionComplete`.

## Screenshots

- Captures are not byte-stable. Playgrounds pick variants with `Math.random`, and the caret and timing-driven demos vary run to run. Compare the content area by pixel diff, never by hash, and do not recommit `apps/demo/screenshots/` for noise.
- Recapture the pages whose content changed and leave noise-only files (changelog, compare) alone. The `playground-shuffled` captures are redone in their own commit, since their random variant makes the diff noisy and their sidebar must sit at the same y as every other capture. A renderer pin change is the exception: it recaptures all of `apps/demo/screenshots/`, in commits by page group, and a file whose noise dominates keeps its committed value (the tooltip's rotated label, switch and slider thumbs, text drawn through a transform matrix, layout morphs at rest).
